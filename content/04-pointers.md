ეს ყველაზე მნიშვნელოვანი თემაა. QGIS-ის API-ში ყოველ მეორე ფუნქციას აქვს `*` ან `->`: `QgsMapLayer *layer`, `layer->name()`. ამ თავის შემდეგ ისინი გასაგები იქნება.

## მეხსიერება და მისამართი

როცა ცვლადს ვქმნით, კომპიუტერი მეხსიერებაში (RAM) ადგილს გვიმზადებს. წარმოიდგინე მეხსიერება უზარმაზარ საწყობად, სადაც უამრავი ყუთია და თითოეულს **მისამართი** (ნომერი) აქვს. ცვლადის მნიშვნელობა ერთ-ერთ ამ ყუთში დევს.

მანამდე ცვლადს მხოლოდ სახელით მივმართავდით (`layerCount`). C++-ს შეუძლია გვითხრას მისი **მისამართიც**, და სწორედ ამაზეა აგებული **მაჩვენებელი** (pointer): ცვლადი, რომელიც მნიშვნელობას კი არა, სხვა ცვლადის მისამართს ინახავს.

::: analogy კურიერი
კურიერს მძიმე ამანათი მოუვიდა. ის მას ადრესატთან კი არ მიაქვს, არამედ ეუბნება: „ამანათი ამ საწყობის ამ მისამართზეა“. მაჩვენებელი არის სწორედ **მისამართი**, არა თავად ამანათი. ბევრად იაფია მისამართის გადაცემა, ვიდრე მილიონობით წერტილიანი ფენის კოპირება.
:::

ეს QGIS-ისთვის არსებითია: ფენა შეიძლება უზარმაზარი იყოს, ამიტომ ფუნქციებს ხშირად თავად ფენას კი არა, მისი მისამართის გადავცემთ.

ორი სიმბოლო:

| სიმბოლო | სახელი | რას აკეთებს |
|---|---|---|
| `&x` | address-of | აბრუნებს `x`-ის მისამართს |
| `*p` | dereference | გადადის მისამართზე და კითხულობს მნიშვნელობას |

ტიპის გვერდით `*` ნიშნავს „ეს მაჩვენებელია“: `int *ptr` ნიშნავს „მაჩვენებელი `int`-ზე“.

::: speaker
კურიერის ანალოგია აქ ძირითადია: მისამართი ≠ ამანათი. სანამ კოდზე გადახვალ, სთხოვე აუდიტორიას, ჩამოაყალიბონ, რატომ არ გვინდა მილიონობით წერტილიანი ფენის კოპირება.
:::

## პირველი მაჩვენებელი

```cpp ptr.cpp
#include <iostream>

int main() {
    int layerCount = 5;
    int *ptr = &layerCount;

    std::cout << "Layer count: " << layerCount << "\n";
    std::cout << "Address: " << ptr << "\n";
    std::cout << "Value at address: " << *ptr << "\n";
    return 0;
}
```

```output
Layer count: 5
Address: 0x7ffd5c3a1a24
Value at address: 5
```

გავარჩიოთ:
- `int layerCount = 5;` — ჩვეულებრივი ცვლადი;
- `int *ptr = &layerCount;` — `ptr` არის მაჩვენებელი და მასში ჩაიწერა `layerCount`-ის მისამართი;
- `ptr` დაბეჭდავს მისამართს, `*ptr` კი „გადადის ამ მისამართზე და ამოიღებს მნიშვნელობას“, ანუ `5`-ს.

::: note
მისამართი ყოველ გაშვებაზე და ყოველ კომპიუტერზე განსხვავებულია (Windows-ზე ის ასე გამოიყურება: `000000BF7C3BF970`). მნიშვნელობა კი ერთი და იგივეა.
:::

სამი ხაზი = სამი ფაქტი: **რა ძევს** (`5`), **სად ძევს** (მისამართი), **რას ვპოულობთ იქ** (`*ptr`).

## struct — საკუთარი ტიპი

ბევრი რამ ერთ ცვლადში არ ეტევა. ფენას აქვს სახელიც და ობიექტების რაოდენობაც. ასეთ შემთხვევაში ვქმნით **struct**-ს: ტიპს, რომელიც რამდენიმე ცვლადს აერთიანებს.

```cpp
struct Layer {
    std::string name;      // ფენის სახელი (ტექსტი)
    int featureCount;      // ობიექტების რაოდენობა
};

Layer rivers{"Rivers", 42};    // ახალი ცვლადი: სახელი Rivers, 42 ობიექტი
std::cout << rivers.name;      // წერტილით ვუკავშირდებით წევრებს
```

`name` და `featureCount` არის `Layer`-ის **წევრები**. ობიექტის წევრთან წერტილით მივდივართ: `rivers.name`. struct-ის უფრო ძლიერ ვერსიას (**class**) თავი 06-ში გავეცნობით.

## მაჩვენებელი ობიექტზე: ისარი

მაჩვენებელი ხშირად მიუთითებს მთელ ობიექტზე. მაშინ წევრთან მისასვლელად წერტილის ნაცვლად `->` (ისარი) გამოიყენება.

```cpp layer_ptr.cpp
#include <iostream>
#include <string>

struct Layer {
    std::string name;
    int featureCount;
};

int main() {
    Layer rivers{"Rivers", 42};
    Layer *ptr = &rivers;

    std::cout << ptr->name << ": " << ptr->featureCount << "\n";

    ptr->featureCount += 8;                       // იგივეა, რაც (*ptr).featureCount += 8
    std::cout << rivers.featureCount << "\n";
    return 0;
}
```

```output
Rivers: 42
50
```

ხედავ? `ptr`-ით ცვლილება პირდაპირ `rivers`-ს შეეხო, რადგან ორივე ერთსა და იმავე ობიექტზე მიუთითებს, კოპირება არ მომხდარა. `+=` ნიშნავს „დაუმატე“: `featureCount += 8` იგივეა, რაც `featureCount = featureCount + 8`.

::: tip წესი
ობიექტზე — `.` (`rivers.name`), მაჩვენებლით — `->` (`ptr->name`). ზუსტად ამიტომ გვაქვს QGIS-ში `layer->featureCount()`.
:::

## nullptr — „ფენა არ არის არჩეული“

მაჩვენებელი შეიძლება არაფერზე მიუთითებდეს. ამას `nullptr` ჰქვია და ნიშნავს „ცარიელი მისამართი“.

```cpp nullptr.cpp
#include <iostream>
#include <string>

struct Layer {
    std::string name;
    int featureCount;
};

int main() {
    Layer *activeLayer = nullptr;

    if (activeLayer == nullptr) {
        std::cout << "No active layer\n";
    } else {
        std::cout << activeLayer->name << "\n";
    }
    return 0;
}
```

```output
No active layer
```

ეს QGIS-ის ყოველდღიური სიტუაციაა: ფუნქცია `iface->activeLayer()` აბრუნებს `nullptr`-ს, თუ ფენა არ არის მონიშნული. `if (...) {...} else {...}` არის პირობის შემოწმება: თუ პირობა სრულდება, სრულდება პირველი ბლოკი, წინააღმდეგ შემთხვევაში მეორე.

თუ Python-ს იცნობ, `nullptr` მისი `None`-ის ანალოგია:

::: compare
```python
layer = iface.activeLayer()
if layer is None:
    print("No active layer")
```

```cpp
QgsMapLayer *layer = iface->activeLayer();
if (layer == nullptr) {
  qDebug() << "No active layer";
}
```
:::

::: warn ხშირი შეცდომა
`nullptr`-ზე `->` გამოძახება პროგრამას ამსხვრევს (segmentation fault / crash). მაჩვენებელი ყოველთვის უნდა შეამოწმო `nullptr`-ზე, სანამ მას გამოიყენებ.
:::

::: note ორი სხვადასხვა შემოწმება
`ptr != nullptr` ნიშნავს მხოლოდ, რომ მაჩვენებელს რაღაც მისამართი უწერია. ის **არ გარანტირებს**, რომ იმ მისამართზე ობიექტი ჯერ კიდევ არსებობს (იხ. ჩამოკიდებული მაჩვენებელი ქვემოთ). ეს ორი რამ ერთმანეთისგან განსხვავდება: „მაჩვენებელი ცარიელი არ არის“ და „ობიექტი ცოცხალია“. მეორეს მხოლოდ ობიექტის სიცოცხლისა და მფლობელობის წესები განსაზღვრავს (თავი 08).
:::

QGIS-ში ფენის ტიპის გასარკვევად გამოიყენება `qobject_cast`: Qt-ის ობიექტებისთვის განკუთვნილი უსაფრთხო გარდაქმნა, რომელიც `nullptr`-ს აბრუნებს, თუ ობიექტი მოთხოვნილი ტიპის არ არის. მას თავი 07-ში `dynamic_cast`-თან შევადარებთ.

## ჩამოკიდებული მაჩვენებელი

::: warn საშიში ადგილი
თუ ობიექტი აღარ არსებობს, მაჩვენებელი მაინც ინახავს ძველ მისამართს. ეს ჰგავს კურიერს, რომელიც მისამართზე მიდის, სადაც სახლი უკვე დაანგრიეს.
:::

```cpp dangling.cpp
int *makeCounter() {
    int count = 10;
    return &count;      // შეცდომა: count ფუნქციის დასრულებისას იშლება
}
```

`count` **ლოკალური ცვლადია**: ის მხოლოდ ფუნქციის შიგნით არსებობს და მისი დასრულებისას იშლება. დაბრუნებული მისამართი უკვე არავის ეკუთვნის. ასეთ მაჩვენებელს ჩამოკიდებული (dangling) ჰქვია. მაჩვენებლის გამოყენება უსაფრთხოა მხოლოდ მანამ, სანამ ობიექტი ცოცხალია, ანუ ობიექტის **სიცოცხლის ციკლი** და **მფლობელობა** (ვინ არის პასუხისმგებელი მის წაშლაზე) განსაზღვრავს, როდის შეიძლება მაჩვენებლის გამოყენება. ამ საკითხს თავი 08 ეძღვნება.

## სავარჯიშო და შეჯამება

::: exercise სავარჯიშო
1. შექმენი `struct Parcel { std::string owner; double area; };`. გააკეთე მაჩვენებელი და `->`-ით გამოიტანე მფლობელი და ფართობი.
2. ფართობი გაზარდე 100 კვ.მ-ით მაჩვენებლის საშუალებით და შეამოწმე თავდაპირველ ობიექტში.
3. შექმენი `Parcel *p = nullptr;` და დაამატე შემოწმება, რომ პროგრამა არ დაიმსხვრეს.
:::

::: summary შეჯამება
- მეხსიერების ყოველ ადგილს მისამართი აქვს.
- მაჩვენებელი ინახავს **მისამართს**; `&` მისამართს იღებს, `*` მნიშვნელობას კითხულობს.
- `struct` რამდენიმე ცვლადს ერთ ტიპად აერთიანებს; წევრებთან წერტილით ვუკავშირდებით.
- ობიექტზე მაჩვენებლით ვიყენებთ `->`-ს.
- `nullptr` = „არაფერზე მიუთითებს“; ყოველთვის შეამოწმე გამოყენებამდე.
- ლოკალური ცვლადის მისამართს ფუნქციიდან არ აბრუნებენ.
:::
