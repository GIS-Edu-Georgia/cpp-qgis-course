**Qt** არის C++-ის ფართო ბიბლიოთეკა („ფრეიმვორკი“): ფანჯრები, ღილაკები, ტექსტი, კონტეინერები, ფაილები და მრავალი სხვა. QGIS Qt-ზეა აგებული, ამიტომ API-ში `std::string`-ს თითქმის ვერ ნახავ: ყველგან `QString`, `QList`, `QVariant`. ამ თავში იმ მინიმუმს ვისწავლით, რომელიც QGIS-ის კოდის წასაკითხად საჭიროა.

Qt-ის კლასები `Q`-ზე იწყება და დიდი ნაწილი თავის header ფაილში ცხოვრობს (`#include <QString>`). QGIS-ის საკუთარი კლასები კი `Qgs`-ზე იწყება.

## QString

`QString` არის ტექსტის ტიპი, ისევე როგორც `std::string`, მაგრამ Qt-ისთვის გაწყობილი. ის Unicode ტექსტს ინახავს, ამიტომ ქართული ასოებიც პრობლემის გარეშე მუშაობს და ბევრი მოხერხებული ოპერაცია აქვს.

```cpp
QString name = QStringLiteral("მტკვარი");
QString info = QString("%1: %2 კმ").arg(name).arg(1364);

qDebug() << info.length();
```

- `QStringLiteral("...")` — ტექსტი, რომელიც კომპილაციისას მზადდება (ეფექტურობისთვის, ამჟამად ჩვეულებრივ ბრჭყალებად წაიკითხე);
- `%1` და `%2` — ადგილები, რომლებშიც `.arg(...)` მნიშვნელობებს ჩასვამს თანმიმდევრობით; შედეგი: `მტკვარი: 1364 კმ`;
- `qDebug() << ...` — Qt-ის გზა, ტექსტი დიაგნოსტიკისთვის კონსოლში გამოვიტანოთ (როგორც `std::cout`).

| ოპერაცია | Python | Qt |
|---|---|---|
| სიგრძე | `len(s)` | `s.length()` |
| ნაწილი | `s[2:5]` | `s.mid(2, 3)` |
| ჩანაცვლება | `s.replace(a, b)` | `s.replace(a, b)` |
| ფორმატირება | `f"{a}: {b}"` | `QString("%1: %2").arg(a).arg(b)` |
| რიცხვად | `int(s)` | `s.toInt()`, `s.toDouble()` |
| std::string-ში | | `s.toStdString()` |

::: warn ქართული და std::string
`toStdString()` UTF-8-ს აბრუნებს. კონსოლში ქართული ტექსტი მხოლოდ მაშინ გამოჩნდება სწორად, თუ ტერმინალი UTF-8-ზეა. `qDebug()`-ით დაბეჭდვისას ტექსტი ბრჭყალებშია (`"..."`), `qDebug().noquote()` კი ბრჭყალებს გაუქმებს.
:::

## QList

`QList<T>` არის Qt-ის სია, `std::vector`-ის ძმა (თავი 09): ელემენტები ერთმანეთის გვერდით ინახება და ზომა საჭიროებისას იზრდება. `<T>` ისევ ელემენტის ტიპია.

```cpp
QList<QString> cities = {"Tbilisi", "Batumi"};
cities.append("Kutaisi");
for (const QString &c : cities) {
    qDebug() << c;
}
```

გამოძახება `append`, `size()`, `[]`, `contains()`. QGIS-ში ფენების სია არის `QList<QgsMapLayer *>`, მაგალითად `QgsProject::mapLayersByName(...)` სწორედ ამას აბრუნებს.

## QVariant — უნივერსალური ყუთი

`QVariant` ერთ მნიშვნელობას ინახავს ნებისმიერი ტიპისას: რიცხვი, ტექსტი, თარიღი, ან „არაფერი“ (NULL).

```cpp variant.cpp
#include <QString>
#include <QVariant>
#include <iostream>

int main() {
    QVariant population = 1200000;
    QVariant city = QString("Tbilisi");
    QVariant lat = 41.7151;
    QVariant unknown;                     // NULL

    std::cout << population.toInt() << "\n";
    std::cout << city.toString().toStdString() << "\n";
    std::cout << lat.toDouble() << "\n";
    std::cout << std::boolalpha << unknown.isNull() << "\n";
    return 0;
}
```

```output
1200000
Tbilisi
41.7151
true
```

::: tip
`QVariant` არ „იცის“ წინასწარ, რა ტიპია შიგნით, ამიტომ კითხვისას თავად ვირჩევთ `toInt()`, `toString()`, `toDouble()`. თუ გარდაქმნა შეუძლებელია, შედეგი ნულოვანი ან ცარიელია.
:::

## QgsAttributes — ატრიბუტების ცხრილის ერთი სტრიქონი

ახლა გასაგებია `QgsAttributes` გვერდი, რომლითაც კურსი დაიწყო. ატრიბუტების ცხრილში ობიექტის ერთი სტრიქონი სხვადასხვა ტიპის მნიშვნელობებისგან შედგება (ტექსტი, რიცხვი, ათწილადი, NULL). ამიტომ `QgsAttributes` არის `QVariant`-ების მიმდევრობა: ფენის ცხრილის ერთი ჩანაწერი. თითოეული ელემენტი ერთი ველის მნიშვნელობაა.

```cpp attrs.cpp
#include <QList>
#include <QString>
#include <QVariant>
#include <iostream>

int main() {
    // ველები: name, length_km, comment
    QList<QVariant> attrs = {
        QVariant(QString("Mtkvari")),
        QVariant(1364),
        QVariant(),
    };

    for (const QVariant &v : attrs) {
        std::cout << (v.isNull() ? "NULL" : v.toString().toStdString()) << "\n";
    }
    return 0;
}
```

```output
Mtkvari
1364
NULL
```

ახსნა: სიაში სამი ელემენტი ძევს: ტექსტი, რიცხვი და ცარიელი `QVariant()` (უცნობი მნიშვნელობა, NULL). ციკლში `for (const QVariant &v : attrs)` თითოეულს გადავხედავთ; `v.isNull()` ამოწმებს, ცარიელია თუ არა; `v.toString()` ნებისმიერ მნიშვნელობას ტექსტად გადააქცევს; `? :` არის „თუ... მაშინ... თორემ...“: `პირობა ? თუ_ჭეშმარიტია : თუ_მცდარია`.

თუ Python-ს იცნობ, შედარება:

::: compare
```python
feature = layer.getFeature(1)
print(feature.attributes())
# ['Mtkvari', 1364, NULL]
```

```cpp
QgsFeature feature = layer->getFeature(1);
QgsAttributes attrs = feature.attributes();
QVariant name = attrs.at(0);
```
:::

## QObject-ის ხე

`QObject` არის Qt-ის ბაზისური კლასი: მისგან მოდის ყველა ფანჯარა, ღილაკი და QGIS-ის ბევრი კლასიც (`QgsMapLayer`, `QgsProject`). მისი მნიშვნელოვანი თვისებაა, რომ `QObject`-ები მშობელ-შვილის ხეში ცხოვრობენ. როცა მშობელი იშლება, თავის შვილებსაც წაშლის. ამიტომ Qt-ში ხშირად `new` გვხვდება `delete`-ის გარეშე (კონტრასტია თავი 08-ის წესებთან: აქ მფლობელი მშობელი ობიექტია).

```cpp
auto *dialog = new QDialog();
auto *button = new QPushButton("OK", dialog);   // dialog არის მშობელი
// delete dialog;  ->  button-იც ავტომატურად წაიშლება
```

## signals და slots

გრაფიკულ პროგრამაში ბევრი რამ მოვლენების საპასუხოდ ხდება: მომხმარებელმა დააჭირა ღილაკს, პროექტს დაემატა ფენა. Qt ამას ხსნის **signal/slot** მექანიზმით: signal არის „რაღაც მოხდა“, slot — „ამაზე რეაგირება“. `connect` მათ აკავშირებს.

```cpp
connect(QgsProject::instance(), &QgsProject::layersAdded,
        this, &MyTool::onLayersAdded);
```

ან lambda-თი, დამატებითი მეთოდის გარეშე:

```cpp
connect(button, &QPushButton::clicked, this, [this]() {
    qDebug() << "clicked";
});
```

`connect(გამომგზავნი, &კლასი::signal, მიმღები, &კლასი::slot)`: ოთხი არგუმენტია. მეორე მაგალითში ბოლო არგუმენტი lambda-ა (თავი 09), ანუ ადგილზე დაწერილი პატარა ფუნქცია, რომელიც ღილაკზე დაჭერისას შესრულდება. `this` არის მიმდინარე ობიექტი, რომელშიც ვიმყოფებით.

::: note Qt-ის კოდის აწყობა
Qt-ზე დაწერილ კოდს აწყობისას Qt-ის ბიბლიოთეკები სჭირდება (თავი 12-ში CMake-ით დავაკავშირებთ). ამ თავის მაგალითები QGIS-ის გარეშეც იკომპილება, თუ Qt დაგიყენებია.
:::

::: analogy საფოსტო ყუთი
signal არის ზარის ხმა კარზე: ის არავის ეუბნება, ვინ გაიგონებს. slot არის ის, ვინც ზარზე რეაგირებს. `connect` ამათ ერთმანეთს აკავშირებს და გამომგზავნს მიმღები არ აინტერესებს.
:::

PyQGIS-ში იგივეა: `layer.selectionChanged.connect(handler)`.

## სავარჯიშო და შეჯამება

::: exercise სავარჯიშო
1. შექმენი `QList<QVariant>` ფენის ჩანაწერისთვის: სახელი (ტექსტი), მოსახლეობა (`int`), ფართობი (`double`). დაბეჭდე თითოეული ელემენტი.
2. შექმენი `QMap<QString, QVariant>` იგივე მონაცემით და გამოიტანე ველი სახელით.
3. წაიკითხე `QgsFeature::attribute` მეთოდი api.qgis.org-ზე და ჩამოწერე მისი ორი ვარიანტი.
:::

::: summary შეჯამება
- `QString` = Unicode ტექსტი, `QList<T>` = მასივი, `QVariant` = უნივერსალური მნიშვნელობა.
- `QgsAttributes` = `QVariant`-ების მიმდევრობა.
- `QObject` ხე თავად ასუფთავებს შვილებს.
- signal/slot აკავშირებს „მოხდა“ და „რეაგირება“ ერთმანეთს.
:::
